# Релиз: жизненный цикл заказа и деньги

Параметры (решение владельца): принятие заказа — **8 секунд**, бесплатное
ожидание — **2 минуты**, оплата — **только наличными**, везде **целые рубли**,
**штрафов за отмены и пропуски нет**.

## Статусы заказа (единый источник — `backend/app/order_states.py`)

```
created ──take──▶ accepted ──arrive──▶ arrived ──start──▶ in_progress ──complete──▶ completed
   ▲                │                                              │
   └──decline───────┘ (отказ/таймаут)                             │
   ▲                                                              │
   └────────────────── executor_cancel (после принятия) ──────────┘
```

- `assigned` — оператор назначил исполнителя; тому даётся **8 секунд** на
  «Принять», по таймауту заказ возвращается в ленту (`decline`, без штрафа).
- `arrived` — «Я на месте»: с этого момента идёт ожидание (2 мин бесплатно,
  дальше 15 ₽/мин, максимум 10 платных минут). Считается сервером в `start`.
- Любое действие может выполнить только исполнитель заказа (Bearer-токен)
  или сотрудник (cookie админки/оператора). Незащищённых эндпоинтов
  жизненного цикла больше нет; дубль `executor-action` и мёртвые
  `AvailableOrders.jsx` / `Summary.jsx` удалены.

## Деньги

- Клиент платит **наличными** исполнителю. На баланс ничего не начисляется.
- При завершении с баланса исполнителя списывается **комиссия**
  (`ExecutorBalanceOp.type = "commission"`, сумма отрицательная).
- `pricing.rub()` — все суммы в целых рублях (половина рубля вверх).
  Копеек в проекте нет; существующие данные нормализуются SQL при деплое.

## Таймауты (`_order_timeout_watcher`, опрос 2 с)

1. Назначенный заказ не принят за 8 с → снова `created` в общем пуле.
2. Заказ без исполнителя ждёт > 5 мин → `cancelled` с уведомлением.
   **Предзаказы (`scheduled_at` в будущем) не отменяются.**

## Фронт

- Исполнитель: Принять (обратный отсчёт) → Я на месте → Начать поездку →
  Завершить; кнопка «Отказаться» после принятия. Список «Мои заказы»
  опрашивается каждые 3 с.
- Клиент: статус «Исполнитель на месте», отмена доступна до начала поездки.
- Админка: статус «На месте», фильтр по статусу, комиссия в истории баланса.
